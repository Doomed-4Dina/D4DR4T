# Security policy

## Project status

D4DR4T is an archived, documentation-only defensive design concept. It has no supported executable code, deployment, package, or release. The current security boundary is the documentation in this repository.

## Reporting a concern

For a documentation problem that is not sensitive, open a GitHub issue with a concise description and the affected section.

For a concern that could put people, systems, or data at risk, do not publish operational details. Use GitHub's **Report a vulnerability** option if it is available for this repository. If private reporting is unavailable, open a minimal issue asking the maintainer to establish a private contact channel; include no exploit steps, secrets, personal data, or identifying details in that issue.

Reports should describe the impact, the affected document or design assumption, safe reproduction conditions using synthetic data, and a proposed mitigation. Do not test against systems you do not own or lack written authorization to assess.

## Coordinated handling

The maintainer will make a best-effort acknowledgement within seven days, assess the report, and coordinate a documentation correction when appropriate. Public disclosure should wait until the issue is understood and a safe correction is available. Because the project is archived and has no runtime, no support or remediation deadline is guaranteed.

## Out of scope

Requests or reports involving credential or session collection, persistence, stealth or evasion, destructive controls, boot loops, operating-system kill techniques, secondary remote-access tool installation, covert surveillance, or unauthorized access are outside this project's scope and will not be implemented.
